Changed

- Configuration and OAuth credentials now use SQLite as their sole durable authority. Legacy YAML and credential files are one-time import sources; later dashboard and token-refresh changes are saved in the database, not watched files or asynchronous YAML mirrors.
- The server no longer watches files: config and credential commits from other SQLite connections (CLI sign-ins, `config import`) are picked up within one second. Credentials load from SQLite only; edits to the private credential cache are ignored and overwritten by the next write, refresh or startup. Config reload log lines name the added, removed or changed resources without values. Changing `worker-threads` reports `restart_required` unless `TOKIO_WORKER_THREADS` overrides it.
- Legacy credential import scans only top-level JSON files, including symlinks to files. SQLite cooldown saves are coalesced through one background writer and drained on graceful shutdown. Legacy `.cds` files are imported once from the legacy `auth-dir`; a workspace `.cds` is ignored when SQLite is configured at runtime construction.
- Configuration administration now uses `/admin/v1` resources with stable IDs, atomic apply, revision history, dry runs and redacted export. Revision ETags prevent stale writes (412), validation errors identify invalid fields (422), and config restore never restores revoked credentials. The old v0/v8 config endpoints are removed.
- Use `--db` or `COOK_DB` consistently for server, login and config commands. `config import`, `export`, `validate` and `backup` support migration and recovery; selected legacy PostgreSQL, object-store or git config backends fail with migration guidance instead of acting as runtime authorities. Containers need a persistent database directory.
- `/admin/v1` reads, revisions and effective config mask secrets as `$secret`; the credential list masks API-key `account` values, and per-key usage is keyed by `auth_index` instead of `base-url|key`. Plaintext remains available through explicit `GET /admin/v1/export?include_secrets=true`, credential download (`/v8/management/credentials/download` and its v0 alias), the authenticated usage queue (`observability/usage/queue`, v0 `usage-queue`, and RESP), and plugin host callbacks. Usage queue records carry the provider key in `source` and the client key in `api_key`; protect management-key access and trusted plugins accordingly. A write that keeps a stored key (`$secret`) while changing its `base-url`, `proxy-url`, headers or provider type is refused with `422 secret_destination_changed`; send the key again to change where it goes.
- Plugin configs accept `$secret` only as the whole config to preserve the stored opaque value. Nested placeholders return `422 opaque_config_requires_replacement`; re-enter the complete config instead. The old v0 `/plugins/{id}/config` routes are removed; use `/admin/v1/r/plugin/{id}`.
- PostgreSQL, object-store and git storage support is removed. Export from those stores with a previous release, then `config import` the result.
- Keep SQLite databases, WAL/SHM files, secret exports and backups private. `config backup` uses SQLite's `VACUUM INTO` for a consistent snapshot; copying only a live main database file is unsafe, and logical credential deletion does not promise physical erasure from disks or retained backups.
