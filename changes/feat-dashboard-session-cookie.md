Security

- The dashboard no longer keeps the management key in browser storage. Signing in sends the key once and the server answers with an `HttpOnly`, `SameSite=Strict` session cookie that lasts 7 days, or 30 with "Remember on this device". Signing out revokes the session on the server, and the other tabs sign out once the server confirms; when it does not confirm, the dashboard says so and stays signed in. A sign-in that another tab's sign-out interrupts ends the session the server opened for it. Changing `management.secret-key` or restarting the server ends every session, and restoring an earlier secret brings none back. Cookie-authenticated requests, reads included, are refused when the browser reports another origin, such as another port on the same host, or when they lack the dashboard's `X-Cook-Dashboard` header, so a page cannot use the cookie through an image, form or link, and `curl` with the cookie is refused. Every Management API answer to an authenticated request, by key or cookie, carries `Cache-Control: no-store`, so a shared cache stores none of them. The TUI, the command line and other API clients keep sending the key as before.
