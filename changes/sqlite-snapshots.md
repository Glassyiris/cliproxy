Changed

- The configured SQLite database is one standalone file you can copy while cook-router runs and restore on its own. It has no WAL, SHM or journal companions; the service works in a private temporary database and atomically republishes the file after every committed change, and an interrupted session resumes its valid working state before republishing.
- One running service owns its database. Configuration and credentials are served from memory and SQLite opens only for a load or a save, so an idle service no longer wakes every second to check the database.
- Offline commands that change the database, including `config import` and local logins, refuse a database another process owns. Use `--management-base-url` to import configuration or save a login through the running service; these commands read the management key from `--password`, from `COOK_ROUTER_MANAGEMENT_KEY`, or from a terminal prompt that does not echo; read-only `config export`, `config validate`, `config backup` and `config listener` still work and read the latest published file.
- Replacing the database file behind a running service no longer changes that service. Restore a backup with the service stopped; after an unclean exit, follow the cold-restore steps in docs/CONFIGURATION.md so a surviving working database does not take precedence.
- A shutdown whose final cooldown save fails now reports an incomplete stop instead of a clean one.
